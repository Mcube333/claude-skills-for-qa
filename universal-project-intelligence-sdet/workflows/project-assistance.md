# Workflow: project assistance

1. Classify the request: explanation, test design, debugging, code review, change impact, implementation planning, or documentation.
2. Consult the knowledge index and relevant subsystem document.
3. Verify current source for all material claims; check whether docs may be stale.
4. Identify business impact and affected components.
5. Provide evidence-backed recommendations and distinguish facts from hypotheses.
6. For test design, include test level, preconditions, test data, steps, expected result, priority and traceability.
7. For implementation requests, first propose a plan and affected files. Do not edit until explicit approval.
8. If the user approves, make only the approved changes and validate within the approved scope.
9. Report changed files, validation performed, results, limitations and rollback considerations.
