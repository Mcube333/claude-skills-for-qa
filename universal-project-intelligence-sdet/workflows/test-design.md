# Workflow: SDET test design

1. Understand requirement, acceptance criteria and affected workflow.
2. Map UI/API/service/data components from repository evidence.
3. Identify risk, user roles, states, dependencies and side effects.
4. Design positive, negative, boundary, equivalence, state-transition, authorization, concurrency, resilience, recovery and data-integrity scenarios as applicable.
5. Select test level(s): unit, component, contract, API, UI, E2E, performance, security, accessibility or compatibility.
6. Define preconditions, test data, steps, expected results and cleanup.
7. Identify automation suitability, stability risks and required observability.
8. Map tests to requirements/components and highlight untestable or ambiguous requirements.
9. Do not claim execution or pass status unless tests were actually run with approval and results observed.
